# 后续想法

本文件只收录尚未完成或需要继续验证的事项。优先级依据数据风险、主工作流影响和实际使用频率确定。

## P0：正式补齐数据安全验收

### 1. 写入失败

目标：模拟 Markdown 或 sidecar 无法写入，确认旧内容不丢失、界面提示明确、恢复后可以继续。

验收：

- 原 Markdown 保持完整。
- 原索引保持可读取。
- 临时文件或备份可用于恢复。
- 不产生“界面显示成功但实际未保存”。

### 2. sidecar 损坏

目标：人为制造无效 JSON，确认插件停止危险覆盖并从备份或 Markdown 恢复。

验收：

- 无效文件被识别。
- 原文件被保留或隔离。
- 不把空数据覆盖到现有索引。
- 用户能看到可理解的错误信息。

### 3. 跨界面同步

目标：在正文弹窗新增、修改或删除笔记后，侧边栏和详情页立即一致。

验收：

- 三个界面显示同一原文。
- 笔记数量、顺序和内容一致。
- 删除单条笔记不影响划线。
- 不需要重启插件才能更新。

## P1：减少长期维护风险

### 1. 统一阅读片段展示组件

把侧边栏摘要卡、正文完整卡和详情页完整卡建立在同一标准数据对象上。允许外观不同，不允许内容解释不同。

### 2. 增加解析诊断

当 Markdown 片段解析失败时，记录：

- 书籍标识
- 笔记路径
- 块 ID
- 失败阶段
- 是否已回退

日志不得记录完整隐私内容。

### 3. 增加备份恢复入口

在设置页提供只读检查和明确恢复动作，避免用户直接处理 `.bak`、迁移备份和冲突文件。

### 4. 检查知识笔记来源健康度

识别以下问题：

- 来源块被删除
- 来源笔记被移动
- 同一来源出现多个知识笔记
- 来源元数据缺失

默认只报告，不自动合并或删除。

### 5. 统一书籍路径身份

书籍位于指定目录时，以稳定路径和书籍标识为准，避免引入“不同目录同名书”的无效复杂度。

### 6. 完整实机回归

按用户闭环而不是零散按钮进行回归：

- EPUB：打开、目录、翻页、滚动、单双页、字号、行距和位置恢复
- 标注：纯划线、写笔记、追加、编辑、删除、侧边栏同步和跳回原文
- 词汇：离线查词、AI 翻译、收藏、悬浮卡、掌握、删除和重开恢复
- 图书库：搜索、筛选、排序、封面、状态、书签和阅读器联动
- 知识笔记：提升、重命名、再次打开、来源链接和独立删除

### 7. 继续观察跳转原文

在更多 EPUB、跨章节、连续切书和书籍未打开的状态下验证 CFI 跳转，不以单本测试通过代替整体结论。

### 8. 大型组件继续拆分

只在真实改动需要时逐步拆分阅读器、图书库和样式文件。拆分目标是明确职责，不为了文件变小而制造更多跳转层。

## P2：体验优化

### 1. 单词学习降级为轻量辅助

- 默认隐藏低价值考试标签。
- 保留发音、核心释义、来源上下文和收藏。
- 复习功能保持可用，但不主动打断阅读。

### 2. AI 翻译状态优化

- 清楚区分离线词典结果和 AI 翻译结果。
- 请求失败时保留离线结果。
- 不因 AI 服务不可用影响划线和笔记。

### 3. 移动端与窄屏检查

重点检查：

- 侧边栏宽度
- 弹窗边界
- 顶部操作图标
- 长单词和多标签
- 详情页封面与信息布局

### 4. 阅读统计减负

统计只回答有用问题，例如当前进度、累计时长和近期阅读，不新增没有行动价值的图表。

验收现有统计时应同时核对阅读时间和单词复习时间，并检查周、月、年切换、极小值与图例刻度。

### 5. 第三方智能指令降级

保留现有适配，但需要明确：

- 第三方插件不可用时的提示
- 私有接口或 DOM 改动后的隔离失败
- 不影响高亮、笔记、翻译和保存

## 暂不实施

- 每条划线独立文件
- 云端账号系统
- 自建同步服务
- 复杂间隔重复算法
- 3D 书架或封面流
- 自动删除孤立 Markdown
- 为无法复现的单条历史数据增加永久兼容层

## 评估新想法的标准

任何新功能都先回答：

1. 是否直接增强“阅读到知识笔记”的主流程？
2. 是否会增加数据损坏风险？
3. 是否会让 13 英寸屏幕更拥挤？
4. 是否可由现有 Obsidian 能力完成？
5. 删除这个功能后，核心价值是否仍然成立？

若只提升视觉新鲜感而不改善主流程，默认不做。
