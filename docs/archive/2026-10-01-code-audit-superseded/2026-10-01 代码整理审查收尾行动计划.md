# 代码整理审查收尾行动计划

## 目标与分工

用户希望梳理当前插件中临时产物、废弃实现及值得统一的重复代码。

本窗口负责接续已有审查，补齐必要证据并形成一份可执行清单；不修改代码。另一个窗口负责读取交付清单、复核候选、实施清理和验证。

本计划不是全面架构审计。不要新增架构规划，不继续扩展事务、并发、性能或生命周期风险审查，不要求逐行重读整个仓库。

## 1. 接续已有成果，不重复调查

先读取已有成果与本窗口已经形成的补查结果：

- `docs/plans/2026-10-01 当前代码审查续查记录.md`
- 该记录链接的首轮审查报告及审查框架
- 本窗口已经输出的删除、统一、保留清单
- 最近对 `library-highlight-core.ts`、退出功能残留及覆盖范围的补查

核对当前 Git 状态，区分已有修改与本次文档工作。已有证据直接复用；仅当当前工作区变化影响结论时，重新核对相关位置。不重跑旧审查框架的全部阶段。

以下结论已经调查，不重新展开：

- 冲突处理模块及测试：维持已有删除，不恢复。
- 图片调试链：维持已有删除，不重复列为本次新清理。
- review、smart-command、旧封面等迁移：保留。
- sidecar、事务恢复与备份：保留。
- 构建发布产物、词典及许可文件：保留。
- 词卡截断：行为不同，暂不合并。
- 工具 import 入口：低收益，不单独整改。
- 已记录的并发、回滚及生命周期风险：引用原报告，不继续调查，不设为清理前置任务。

## 2. 仅补尚未闭合的清理证据

### A. 独立详情页残留

沿已经确认退出的详情页核对：

- 详情页专属 CSS 的完整规则块。
- 是否还有直接配套的孤立类型、工具、导出或组件。
- 哪些选择器仍由书架、统计或其他界面共用。

给出准确删除范围。混有共享选择器的规则，注明应保留部分。不逐条审计全部 CSS，不调整当前视觉设计。

### B. `library-highlight-core.ts`

复用已经查出的事实：没有生产调用、HEAD 中已存在、不是当前新增词卡工作的组成部分。

最后核对重导出、动态或脚本入口，以及已有记录是否明确指定现行消费者。交付以下结论之一：

1. 建议删除模块、专属测试及 strict 配置项，并列明位置。
2. 找到具体消费者，保留并给出调用证据。
3. 仍无法判断，写明具体缺失证据，交由实施窗口复核。

测试与 strict 配置引用不能单独证明产品用途。不为保留模块新增入口，不泛泛要求产品确认，不无限追查。

### C. 与退出功能直接相关的现行文档

列出仍把已退出功能描述为现行能力的位置，尤其是 `项目管理/00` 中的详情页规则。

只提出应修正的当前描述；历史版本记录与改动日志不删除，不全面重写管理文档。

### D. 尚未检查的明显残留

利用已有覆盖记录，仅对尚未看过的源码文件和根目录脚本做一次轻量用途核对：是否有产品调用、脚本入口，或明确的迁移、构建、发布用途。

只追查明显孤立、被替代或调试用途的候选；已有明确用途的直接跳过。不构建全仓可达性图，不逐行重读已查文件，不为了凑数量制造删除或统一项。单次定向核对后仍不确定的列为待确认。

## 3. 交付一份最终清单

生成：

`docs/plans/2026-10-01 代码整理审查交付清单.md`

不要再把结论分散到多个新报告；引用已有报告即可。交付清单采用以下结构。

### 3.1 审查结论

简述值得实施的清理与不值得实施的调整。注明只读、未执行代码修改及验证。

### 3.2 建议执行

每项包含：

| 字段 | 要求 |
| --- | --- |
| 路径与位置 | 具体文件、符号或 CSS 规则块 |
| 建议动作 | 删除什么，或统一到哪份现有实现 |
| 依据 | 调用、退出记录、替代实现等证据 |
| 保留边界 | 不能一起删除的内容或不能改变的行为 |
| 验证方法 | 实施后应进行的针对性测试或界面检查 |

只放证据充分的项目。不混入未复现的正确性风险或架构改造建议。

### 3.3 暂不处理

集中列出迁移恢复、语义不同的实现、低收益一致性调整和证据不足项，说明原因及具体证据缺口。

已有工作区删除单列为“维持现状”，不要称为“保留实现”。

### 3.4 文档修正

列出现行描述与已退出功能不一致的位置及建议改法。历史事实保持不变。

### 3.5 覆盖与限制

简短列出已检查的类别与未检查范围，区分引用已有报告的证据和本次补查证据。不声称全仓无残留，不把关键词搜索等同于完整覆盖。

## 4. 边界与完成条件

- 已有成果汇总到一份交付清单，实施者无需重新拼接聊天记录。
- 上述定向补查完成；无法闭合的明确列为待确认，不阻塞整个交付。
- 建议执行项具有准确范围、依据、保留边界及验证方法。
- 本轮仅新增交付文档；不修改源码、样式、配置及用户数据，不运行部署、不删除产物、不提交 Git。
- 无需为了只读审查运行构建或测试；验证由实施窗口在修改后执行。

完成后回复交付文档路径、建议执行项数量和待确认项数量，并明确审查收尾完成。后续交由另一个窗口复核和实施。
