## 1. 任务边界与基线

**用户目标：**识别并删除确实不用或不规范的残留；统一重复、不一致实现；评估复杂混杂职责是否值得拆分，同时保留已认可功能、视觉、数据及兼容行为。

**本轮实际做了什么：**只读检查核心调用链、数据权威与失败路径，查看若干测试、依赖源码、类型与构建配置、CSS片段及管理文档；形成了首轮候选和后续局部线索。没有执行本轮测试或完整`npm run verify`，没有Obsidian实机复现，没有改动仓库或用户数据。

**审查限制：**不是全部56个源文件的逐行审阅；不是完整动态CSS映射、宿主兼容矩阵、生命周期压力测试或重复代码等价性调查。此前曾有输出被截断并误作完整覆盖的声明，现明确撤回；请求的行号范围不等于实际可见覆盖。后续续查笔记中标为“完整读取”的文件也仅代表当时记录的可见源码范围，不替代逐候选复核或运行验证。

**基线：**工作区HEAD曾核对为`5a9be98`；package/manifest为`1.4.1`，manifest最低Obsidian版本`0.15.0`。本任务未修改源码。工作区已有大量修改、删除和未跟踪文件，均非本次审查所作，必须保留；具体状态以当时`git status --short`可见输出为准，不将其归因于本任务。不要运行stash/reset/restore或部署脚本。

**数据禁区：**未读取真实`data.json`、sidecar、EPUB、用户笔记、凭据、索引或日志内容；无新增外部请求。不得用破坏真实数据的方式复现。

## 2. 已核对的架构事实与保留边界

- 核心工作流已有服务边界：高亮事务与Markdown写入、highlight索引、书籍状态、路径更新、知识笔记、词条资产、封面缓存、阅读统计及设置保存队列均有既有实现。不能把“文件大”本身视作拆分理由。
- Markdown是高亮正文、笔记和关联的权威来源；索引承担身份、定位与路由；缓存或投影不得覆盖正文。阅读位置、进度和书签经状态/设置服务保存。清理不得混淆来源身份、CFI、`id`与`blockId`。
- Obsidian宿主适配、`main.ts`服务组装与事件注册是必要边界；不能为了减少行数将宿主API、DOM或文件写入塞进纯领域逻辑。
- 迁移、事务恢复、备份、历史来源链接兼容并不因界面退出而自动成为废代码；review/smart-command迁移仍由启动流程调用，有测试及兼容用途。
- `src/reader-settings.ts`已有缩放、行高、字距、字间距、宽度的共享limits与clamp；不能由此推断所有参数均已统一。参数、单位、默认值、缺失语义仍未形成完整字典。
- `verify`脚本包含普通类型检查、strict检查、测试、构建和main.js语法检查；strict配置只显式列出部分入口，不是全仓strict。本轮未运行这些检查。
- `processFrontMatter`在当前本地Obsidian类型声明标注`@since 1.4.4`，而manifest最低版本为0.15.0；Library元数据写入使用此API。这是兼容性核查需求，不是已复现的兼容故障；不应未经决策改最低版本或增加兼容层。

## 4. 可考虑的结构整理方向（不是实施决定）

1. **封面用例边界：**若确认当前UI直接负责文件写入与缓存关联，应移动完整用例及失败顺序到现有封面服务边界；单纯把JSX拆到新文件不解决责任耦合。
2. **统计纯逻辑：**日期聚合、分类/雷达模型可按需做局部纯函数提取，保留书库UI呈现；不创建图表框架或通用统计层。
3. **阅读器异步资源：**先查清组件、EpubView、react-reader与epub.js的销毁所有权，再决定是否引入最小请求代次/清理。不要把未复现的生命周期候选直接改成架构重写。
4. **启动入口：**`main.ts`做宿主注册和服务组装属合理composition root。可疑启动恢复细节先按数据正确性处理；不为缩短文件而拆出无独立所有权的模块。
5. **纯规则优先复用：**重复逻辑只有在输入、默认值、错误处理、单位与时序均等价后才合并。词条预览/持久化、完整笔记/摘要、不同截断策略等相似外观可能有不同语义。

## 5. 删除/统一候选的判定规则

- 无直接引用不等于无用途；还需查动态命令/事件注册、字符串和DOM选择器、宿主协议、迁移/恢复、构建打包与测试。
- CSS无源码同名字面量不能单独证明无效；类名可能动态拼接或由宿主/依赖提供。
- 相同名字或相似实现不能单独证明重复；需要比对输入输出、默认值、错误、时序、持久化语义。
- 大组件不因行数拆分；只有边界减少实际耦合且保留完整用例事务时才拆。
- 任何涉及持久化字段、命令ID、Markdown元数据、来源链接或已有文件的删除/统一，需兼容与回退方案。
- 先列清单由用户取舍，再分批改；本报告没有授权任何代码删除、视觉调整、依赖升级、部署、提交或发布。
