## 4. 已确认的问题来源

### 宽度与页边距叠加

书架外壳左右已经有 40px；统计页再增加 `padding: 32px 12px`。当 readableLineLength 启用时，统计内容最大宽度是 `var(--file-line-width, 700px)`，居中形成额外空白；关闭时还会增加容器左右各 24px。因此切入统计后，左右边界与书架不一致。

建议让统计复用书架可用内容宽度，取消统计专属正文限宽与额外横向内边距。只消除统计的叠加层，不顺手调整书架宽度或全局 Obsidian 配置。这里“同宽”指同一标签页内的内容左右边界，而非按书籍数量形成的封面行宽度。

### 字号层级偏大且不统一

现有主时长 32px／800 字重，单位 16px；摘要数字 18px／700，摘要说明 11px；标题 18px 内联，图表标题 14px，正文和切换 13px；另有 9px 刻度／日历时长。固定 px 无法完整跟随主题界面字号。

建议使用 `--font-interface`、`--font-ui-small`、`--font-ui-smaller`、`--font-ui-medium` 等现有主题变量。正文和控件以插件基础界面字号为准；主时长保留有限强调，建议约 18–20px／600，而不是强行与小字完全同大。该数值是建议，不是已批准的最终设计。

当前测试主题下，前序实测插件卡片基础字号为 13px；不要把 13px 当作所有主题的固定常量。修改时检查 CSS 和 JSX 内联样式，尤其 SVG 文本与刻度；不要用全局 `* { font-size: ... !important }` 抹平全部层级。

### 留白与边框叠加

统计容器 gap 24px，若子模块又有 margin-bottom 16／24px，两者可能叠加；主时长卡 padding 24px，图表区 padding 20px，顶部标题和切换各有分隔／上下留白。实机表现为首屏大块摘要占据较多高度。

建议区块间距先试 12–16px，模块内部 10–12px；避免 gap 和 margin 重复承担同一间距。摘要可改为一条紧凑概览或轻分组，不需要每个指标都独立重边框。图表、排行、偏好用小标题与细分隔线建立层级。

### 主题颜色不统一

统计 CSS 中有浅色专用 #8C1A1A 暗红、#FBF9F3 米色等，也有固定趋势色和日历色。部分背景规则属于旧 stats-modal，须先判断实际使用。实机当前统计页确实显示暗红主时长和筛选选中态。

建议文字用 text-normal／muted／faint，底色用 background-primary／secondary，边框用 background-modifier-border，交互和图表主色用 interactive-accent。趋势与热力图仍需保持可区分，不能全部改成同一灰色；在浅深主题中验收。

## 5. 推荐的第一轮设计方向

1. 统计内容与书架左右对齐，取消内部正文限宽和额外横向 padding。
2. 紧凑页头：返回入口、阅读统计标题；周／月／年／全部和日期控件尽量在同一工具区，窄屏自然换行，避免强塞一行。
3. 概览区：适度强调总时长，说明文字弱化；阅读天数／在读／已读完／笔记用简洁指标组，保留各时间范围原有条件。
4. 图表区：保留切换与数据，减少外围装饰和留白。不要仅为压低高度裁掉刻度、标签、tooltip 或热力图。
5. 排行与偏好：沿用现有项目和条件，以紧凑行与主题小标题显示。没有数据时保持原有空状态。
6. 全部使用主题字号／配色／radius-s 或 radius-m。尽量不新增 CSS 覆盖层；修改真实生效规则，确认历史重复规则和内联样式优先级。

第一轮不建议删除偏好分析、重写图表库、改成独立新页面、新增设置、引入依赖，或拆分整个大型 LibraryApp。若发现结构问题，只单独记录后续任务。
