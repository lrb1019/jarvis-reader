# 2. 修复方法

`displayReadingSource` 将 epub.js 视图尺寸调用集中在一个适配文件中：

1. 等待一次浏览器布局，供 Obsidian 激活标签。
2. 加载目标所在章节。
3. 等待章节字体加载完成，再等待一次布局。
4. 调用现有视图的 `expand()`，使 iframe 的可滚动范围与应用主题下的正文尺寸一致。
5. 再次定位同一 CFI。

两次定位分别承担加载章节和最终定位，不采用固定毫秒延时或无限重试。每个异步阶段检查请求是否仍属于当前书籍和当前阅读器，较新的高亮跳转可取代旧请求。

# 5. 连续跨章跳转卡住：控制台诊断与修复

- 日期：2026-09-29。
- 影响：连续跳转及关闭重开后，页面停留在当前章节，后续跳转无法完成。
- 现场错误：`TypeError: Cannot read properties of undefined (reading 'attach')`，调用栈为 `Annotations.inject`、`Hook.trigger`、`Rendition.afterDisplayed`。应用磁盘日志只有更新记录，实际错误保存在开发者控制台。
- 直接原因：epub.js 的 `Annotations.remove` 将章节编号清理放在遍历已加载视图的循环内。无视图时，对象被删除、章节编号残留，重新注入时访问不存在的对象并抛错。
- 系统原因：插件在 resized、rendered、relocated 等时机反复清除和重建词卡标记，可能在无视图阶段触发该第三方缺陷；之前没有检验引擎内部标记索引的一致性。
- 之前测试遗漏：分页模拟测试只验证宽度与位置，没有运行真实 epub.js 的标记删除、重新注入过程。
- 恢复：重载插件或重启 Obsidian，销毁已中断的旧阅读器实例。磁盘笔记与索引无需修复。
- 修复：新增 `epub-annotations-adapter.ts`，所有阅读高亮与词卡标记删除统一经过适配方法，清除无效章节编号和重复编号。私有字段依赖已集中标注，升级 epub.js 时需要复核。
- 新检查：直接使用项目安装的 epub.js，证明旧删除流程可抛出同一 attach 异常；验证修复后连续清理、注入、卸载及保留有效标记。
- 验证：`npm run verify` 通过 115 项测试、类型检查、构建及语法检查；本次构建后的真实连续跳转尚未验收。没有删除用户高亮、词卡、笔记或索引数据。

# 6. 第三次跳转出现空白页：事故复盘

- 日期：2026-09-29。
- 影响：连续从 Markdown 返回原文后，章节标题和进度仍显示，但正文区域空白，目标摘录不可见。
- 直接原因：隐藏标签中创建的 epub.js 视图锁定了 0px 高度；标签激活后管理器布局高度已更新到 582px，但既有视图仍保留 `lockedHeight = 0`。重新调用 `expand()` 只计算横向分页宽度，不会修正锁定的高度。
- 系统原因：导航代码只依据目标 CFI 和正文宽度判断可见性，缺少对视图锁定尺寸与当前布局尺寸的一致性检查。epub.js 队列为空、正文 DOM 存在，所以控制台没有新的导航异常。
- 为什么测试遗漏：原分页模拟只模拟宽度收缩，没有模拟隐藏标签首次创建视图时的零高度锁定。
- 恢复：现场只调用 `view.size(607, 582)` 即恢复正文和目标划线；未修改书籍或笔记数据。
- 最终修复：原文跳转等待字体和布局后，先用管理器当前视图尺寸调用 `view.size()`，再 `expand()` 并按同一 CFI 最终定位。
- 新预防检查：增加零高度视图回归测试；实机验收必须检查目标摘录实际可见，不能只看章节标题、页码或 CFI。
- 验证：`npm run verify` 通过 116 项测试、类型检查、生产构建和语法检查。Obsidian-test 重载后，从 Markdown 连续三次跨章跳转，后段、前段、后段目标划线均实际可见；滚动模式、快速连点和其他书籍尚未实测。
