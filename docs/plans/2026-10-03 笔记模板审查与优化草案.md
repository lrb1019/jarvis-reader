## 任务与边界

Task: 审查读书笔记、知识笔记模板，给出可评审默认结构及分批方案。
Task type: 诊断与设计。
User scenario: 从EPUB保存摘录与多条笔记，再提升为独立知识笔记，在Obsidian中继续编辑和回跳。
Current behavior: 读书笔记初始模板可编辑，摘录块固定；知识笔记固定生成，文件名基底为“读书笔记”。
Reproduction: 本轮核查源码、调用链和现有测试；未生成真实用户笔记。
Root-cause evidence: 下文列出生成器、解析器和调用位置。
Target behavior: 紧凑但保留内容层级；个人笔记与引用清楚区分；来源、定位和统计元数据保持稳定。
Completion criteria: 事实、建议、兼容边界、草案和后续验证明确分开。
Scope: 默认结构、设置呈现和新文件生成方案。
Explicitly excluded: 批量迁移旧笔记、重写用户模板、AI自动提炼、新增同步服务、提交或发布。
Affected data and files: 本轮仅计划及管理记录；实施可能涉及settings、book-notes、highlight-core、book-note-document、knowledge-note及对应测试。
Automated verification: 本轮仅文档diff检查；实施阶段完整verify及有意义的解析／持久化回归。
Obsidian verification: 草案尚未渲染验收；后续在测试库用临时样本检查。
Failure handling: 草案不写数据；实施时沿用事务和旧格式解析，不覆盖用户笔记。
Rollback: 本轮可撤回文档；实施回滚恢复生成器，不删除已生成笔记。
Documents to update: 改动日志、接续说明。

## 推荐默认方向

### 1. 读书笔记：按实际阅读积累

推荐新文件不预写全书空章节。属性仍保留bookname、status、rating、tags、start_date、finish_date、created；首次保存摘录时沿用现有插入逻辑创建章节标题。用户需要完整章节骨架时，可继续在自定义模板使用{{toc}}。

不重复添加书名一级标题，因为文件名已表达书名。不开设空白“总结／行动／感想”等必填区域。让用户直接补充内容。

新文件默认模板草案：

```markdown
---
bookname: "[[{{bookname}}]]"
status: unread
rating: 0
tags: []
start_date: ""
finish_date: ""
created: {{created}}
---
```

保存摘录后的结构仍保留现有协议，示意：

```markdown
## 章节标题

> [!note] 章节标题
> 摘录原文。
>
> **笔记**
> created: 2026-10-03 10:00:00
>
> 我的理解。
>
> **时间**
> 2026-10-03 10:00:00
> [返回原文](由插件生成的定位链接)
^稳定块ID
```

上述片段展示兼容底线，不代表这是最终精简排版。第二批才讨论callout标题去重复、时间的紧凑呈现；必须同步验证解析、追加、编辑及多条笔记，不通过样式全局隐藏真实内容。

### 2. 知识笔记：个人表达优先，原文与来源仍完整保留

推荐把已有个人笔记放在前面，引用在后面；不自动生成用户未写过的“结论”。单条笔记不再重复套三级“笔记”标题，多条笔记仍独立分节，不拼成失去边界的一段。

单条笔记草案（占位值仅为设计示例）：

```markdown
---
created: 2026-10-03
source_book: "书名"
source_note: "Reading Notes/书名.md"
source_block: "稳定块ID"
---

## 笔记

我的理解和判断。

*记录于 2026-10-03 10:00*

## 原文

> 完整摘录原文。

## 来源

[[Reading Notes/书名.md#^稳定块ID|返回读书笔记]] · [返回原文](由插件生成的定位链接)
```

多条笔记草案保留：

```markdown
## 笔记

### 笔记

第一条完整内容。

*记录于第一条原有时间*

### 笔记 2

第二条完整内容。

*记录于第二条原有时间*
```

只有原记录存在时间才显示，不新增虚构时间。source字段名称、值及块身份不改；保留旧版来源查找逻辑。来源链接排成一行是新文件的排版建议，旧文件不会重排。

文件名另列小项讨论：先提供可编辑名称，继续按稳定来源查找已存在笔记；不要为了“自动起好名字”接入AI或产生新标题算法。本批不实施命名变化。

### 3. 设置呈现：清楚说明真正可改的范围

- 将当前控件命名为“读书笔记初始模板”，注明只影响新建文件，摘录格式由插件维护。
- 读书笔记初始模板提供恢复默认与本地预览；恢复默认只改设置，不改已有文件。
- 第一批知识笔记先使用改良默认结构，不立即新增任意文本模板编辑器。若后续确需自定义，开放正文布局；稳定来源属性由程序维护，不让用户意外删除。
- 两类存储目录继续独立配置，不绑定书籍目录，不新增文件夹规则。

## 实施顺序与验证门禁

1. 第一批：读书笔记初始模板默认不预铺目录；知识笔记消除单条重复标题、个人笔记优先、保留所有条目与时间／引用／来源，新文件取消固定Jarvis署名。保存过的模板不自动替换，已有文件不改。
2. 第二批：读书摘录块去重复，仅在明确新版协议与兼容解析后实施。先用纯摘录、一条／多条笔记、关联、AI段落、复杂Markdown与旧格式样本证明完整往返。
3. 第三批：模板预览／恢复默认、控件细节和主题字号统一；不扩成复杂模板系统。
4. 后续：窄分栏、深浅主题、放大UI、长引用、多条笔记、来源回跳和改名移动回归。

第一批验证：空模板与用户模板不被覆盖；缺失／无效路径和文件碰撞；完整原文与全部笔记；无重复标题；source_block识别旧文件；读书笔记统计属性读取；生成后关闭重开；移动或改名后重复提升打开既有文件。完整verify之外，在测试库临时样本验收，不能用已保存真实笔记做破坏性实验。

## 结论

优先解决已确认的重复层级和默认文件骨架；不要将“紧凑”实施为抹平Markdown层级或删除来源协议。知识笔记保留用户已有思考，不擅自代写提炼内容。模板优化与卡片CSS排版分别验证。
