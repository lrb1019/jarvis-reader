# 阅读笔记融入 Obsidian 实施方案

## 1. 状态与使用方式

- 日期：2026-09-28。
- 状态：方案已编写，功能尚未实施或验收。
- 调研基线：本地 `1.3.4`，提交 `3dccc38`；实施前重新核对 Git、源码和管理文档。
- 本方案是持续执行文件，阶段完成后在第 9 节登记实际结果。管理文档只保留入口、优先级和状态。
- 已明确目标：在 Obsidian 中阅读、记录想法、关联已有笔记，并从笔记返回书中原文。
- 技术方法属于建议；实施者应先验证生命周期和兼容性，不能把方案描述当作现有能力。
- 当前没有对 Qiaomu Reader 进行实机测试。比较依据为本次读取的公开源码；远端 `main` 会变化，后续引用前记录对应提交。

## 2. 产品方向与范围

### 2.1 主要工作流

阅读 EPUB → 保存原文和个人想法 → 关联或引用到已有笔记 → 继续编辑和写作 → 点击返回原文核对上下文。

保持每本书一份 Markdown，每个阅读片段有稳定块 ID。独立知识笔记由用户按需创建。原文、笔记和关联继续以 Markdown 为依据，索引负责书籍路径、身份与 CFI 定位。

成功场景：用户把一条阅读片段引用到已有主题笔记，几天后仍能查看当时的想法、继续写作，并从该处打开 EPUB 到对应原文。

### 2.2 本方案包含

1. Markdown 返回原文链接及统一导航。
2. 复制带来源的引用、复制原文位置链接。
3. 独立知识笔记命名和可靠的来源识别。
4. 阅读片段格式减负的样例与兼容实现。

### 2.3 不随本方案实施

- 替换 EPUB 引擎、扩大文件格式、重写阅读器或整套存储。
- 自动生成知识内容、自动建立关联、批量拆分所有划线。
- 移除智能指令、删除复习系统或词汇数据。这些另立任务；本方案期间停止扩展相关能力。
- 新增云端服务、外部 AI 调用、复杂模板插件适配。
- 自动重写全部历史笔记、删除孤立文件。
- 自动提交、推送或发布。功能验收与发布分别授权。

## 3. 调研结论与事实纠正

| 项目 | Qiaomu Reader 的已读实现 | Jarvis Reader 的已读实现 | 采用方向 |
| --- | --- | --- | --- |
| 引用输出 | 摘录、书籍链接和原文位置链接组合，可复制 | 有块 ID 和来源块链接，缺少 Markdown 原文回跳 | 借鉴便于复制与回跳的输出 |
| 内容更新 | 根据高亮集合重新生成受管理的 Markdown 区域 | 解析 Markdown 片段，按块修改并检查内容冲突 | 保留本项目正文权威关系 |
| 个人笔记 | 已读路径使用一个评论字段 | 同一片段支持多条笔记和时间 | 保留多条笔记 |
| 知识笔记 | 创建时可选标题、模板，并追加书籍笔记中的新文件链接 | 固定标题“读书笔记”，保存原文、全部笔记和来源块链接 | 改善命名，保持按需创建 |

注意：不能据此宣称对方全部路径都会覆盖手写内容，或所有独立笔记都具有原文回跳。这里只描述实际检查的函数。

2. `src/book-note-document.ts` 的解析依赖 Callout、标签与块 ID。Markdown 可以直接编辑，但不能宣称任意改写结构都受支持。需要用样例明确可编辑范围。

## 4. 统一技术约定

### 4.1 两种链接分别保留

- 笔记来源：Obsidian 的文件／块链接，用于双链、嵌入和查看个人想法。
- 返回原文：插件协议链接，用于打开 EPUB 并定位。默认可见文字为“返回原文”。

两者不能互相替代。关闭插件后普通 Markdown 内容和笔记链接仍可使用，原文定位依赖插件与原书。

### 4.2 位置链接的建议格式

建议使用 `obsidian://jarvis-reader`，包含版本 `v=1`、知识库 `vault`、高亮身份 `highlight`，必要时附 `book` 和 `cfi` 作为定位快照。参数由统一构造函数生成，不在各界面拼接。

实施前先验证现有高亮 ID 的生成规则、全库唯一性及移动书籍后的索引维护。不能只因存在 `id` 字段就假定它跨书唯一。

解析顺序：

1. 校验协议、版本、参数类型与长度；拒绝异常编码、绝对磁盘路径、目录穿越和不支持的文件类型。不执行链接中的命令。
2. 通过稳定高亮身份查找当前索引，优先采用当前路径和 CFI。
3. 身份不存在时，可用链接携带的书籍路径与 CFI 尝试只读定位；不恢复已删除的高亮，不写回索引。
4. 主索引损坏时遵守现有停写规则；任何快照定位都不能覆盖或“修复”索引。
5. 无有效定位信息、书籍缺失或已移动且无法解析时，明确提示，不按同名文件猜测、不自动搜索整库正文。

Markdown 中的 CFI 仅为生成时的位置快照，索引仍是当前定位依据。只有新链接含有效 CFI 快照时才可能在索引缺失后定位；旧笔记不具备这一保证。

统一编码包括 CFI 的括号，防止 Markdown 链接被提前截断。知识库名和路径按 URL 参数编码。普通 Wiki 链接优先使用 Obsidian 的链接生成能力，避免同名文件歧义。

### 4.3 书籍移动和删除

阶段 A 要检查当前重命名／移动处理：若索引已维护最新路径，按身份解析后应继续可用；若没有，则把对应索引和状态更新作为明确子任务，遵循现有保存与回滚规则。未完成前不得宣称支持书籍移动。

删除高亮后，带 CFI 快照的旧链接允许查看原文，但不能重建高亮。删除书籍后保留 Markdown，点击提示书籍缺失。更换 EPUB 内容可能使旧 CFI 失效，不保证自动修复。

## 5. 阶段 A：从 Markdown 返回原文

### 5.1 任务定义

- 任务类型：导航功能及兼容性改动。
- 用户场景：在书籍笔记、其他笔记中的引用或独立知识笔记里点击“返回原文”。
- 当前行为：阅读器已有 CFI 跳转，普通 Markdown 尚未接通。
- 复现：生成片段，切换到 Markdown，检查缺少可触发原书定位的链接。
- 原因依据：`EpubView.jumpToHighlight/jumpToCfi` 已存在；现有知识笔记来源生成的是 Markdown 块链接。
- 目标：书已打开或关闭时均可打开正确书籍并定位，失败可理解且不改正文。
- 数据影响：新片段增加位置链接；不改变索引权威关系，不默认批量改旧笔记。

### 5.2 实现顺序与入口

1. 新建小型纯函数模块（建议 `src/reading-source-link.ts`）：构造、解析、校验链接，测试编码与版本兼容。
2. 在 `src/main.ts` 注册协议处理；将解析、查索引、打开视图、等待加载、跳转编排到统一服务（建议 `src/reading-navigation-service.ts`）。协议入口只转交请求。
3. 复用 `src/workspace-navigation.ts` 同书标签复用逻辑；核对 EPUB FileView 的具体打开方式，不覆盖用户当前 Markdown 标签。
4. 在 `src/EpubView.ts` 接通带 Promise 的定位接口。阅读器就绪信号必须晚于书籍初始化与默认阅读位置恢复，避免跳转被旧进度覆盖；追踪 `src/EpubReader.tsx` 的实际加载回调后再实现。
5. 每次请求分配标识；连续点击以最新请求为准。关闭视图、切书或插件卸载时取消旧请求。捕获异步 `display()` 失败，不能只用同步 `try/catch`。
6. 设置有限的等待时间并给出失败提示；优先使用真实就绪信号，不靠固定睡眠。现有 `currentRendition` 非空不单独作为完全加载的证明。
7. 在统一片段格式化函数中添加来源行，并同步更新解析器，确保位置链接不被读成原文、个人笔记或 AI 内容。
8. 新建知识笔记同时保留来源块链接与原文位置链接。已有文件不自动改写。

新增链接格式必须用旧解析器样例验证回退兼容。若旧版本会把链接读成正文或保存时删除链接，记录限制并调整生成方式，必要时在快照与恢复方案齐备后采用格式版本。

### 5.3 历史笔记处理

首轮仅覆盖新生成内容，并提供“复制原文链接”用于已有片段。历史链接补齐为独立子任务：先只读列出可处理文件和片段数，按块 ID 精确匹配，跳过歧义和损坏内容；展示预览与备份路径，得到批量覆盖授权后执行。重复执行不能重复插入链接。

### 5.4 验证与回退

- 自动测试：中文／空格／括号路径、异常 URL、缺参数、未知版本、重复名称；书已打开／关闭、加载失败、超时、连续点击、关闭中取消；高亮删除、文件缺失、索引损坏；旧格式与新格式解析一致。
- Obsidian：阅读视图、实时预览中的链接激活方式、复制到其他笔记、块嵌入、重启后点击、跨章节和至少两本结构不同的 EPUB；确认同书不重复开标签，导航后不会跳回旧阅读位置。
- 涉及生成笔记时，覆盖保存失败、重载、删除、用户手改和事务回滚。
- 完成条件：上述适用检查通过；未测项标为未验证，移动书籍能力单独记录。
- 回退：恢复代码与匹配构建；新增链接可保留为文本，旧正文和块 ID 不变。不通过恢复整份旧笔记覆盖用户实施后的新内容。

## 6. 阶段 B：把阅读内容用于已有笔记

依赖阶段 A；首轮只增加两个操作，不增加复杂发送目标面板。

### 6.1 两个操作

1. **复制为引用**：读取最新 Markdown 原文，生成引用正文、来源块链接和返回原文链接。默认不附全部个人笔记，以免复制内容超出用户预期；若需要完整片段，可沿用块嵌入方式。
2. **复制原文链接**：生成带“返回原文”标签的 Markdown 链接，不写入任何笔记。

示意输出（链接由代码生成，下列括号内容只是说明）：

```markdown
> 原文摘录。

来源：[[书籍笔记#^片段ID|书名 · 章节]] · [返回原文](位置链接)
```

### 6.2 实现方法与验收

- 共享纯格式化函数；界面从 `BookNoteService` 取得最新正文，不采用旧缓存正文。
- 首轮从已保存片段提供入口；未保存选文另行定义身份与行为，避免自动创建高亮。
- 选用现有片段菜单，保持侧栏、弹窗和详情页输出一致，不在每张卡上堆按钮。
- 测试多行引用、特殊字符、同名笔记、空内容、剪贴板失败和手改后的最新内容。
- 实机把结果粘贴到已有主题笔记，确认来源块正确、原文跳转正确，原书笔记未被改动。
- 回退只移除菜单和格式化入口，用户已粘贴的 Markdown 保留。

## 7. 阶段 C：独立知识笔记可辨认、可找回

### 7.1 先修正来源识别

入口：`src/knowledge-note-store.ts`、`src/knowledge-note-service.ts`、`src/knowledge-note.ts`。

- 新笔记按稳定来源身份保存结构化元数据；先核对高亮 ID 的唯一性，再决定使用单 ID 或必要的组合身份。
- 查找顺序建议：新来源身份字段；现有 `source_note` 与 `source_block` 元数据；旧版来源链接兼容查找。优先利用元数据缓存，必要时读取候选文件，避免每次无条件读取全库正文。
- 多个匹配时展示候选文件供选择，不直接返回第一个，不自动合并或删除。
- 目标笔记移动／改名、来源笔记移动、同名文件、元数据缓存未更新分别测试。连续快速创建要避免重复文件，可用按来源串行执行与创建前复查。
- 已有知识笔记只打开，不用原文或旧笔记覆盖其中继续创作的内容。知识笔记删除后允许用户再次主动创建，源片段保留。
- 移动来源文件时需检查普通路径元数据的更新，不能假定 Obsidian 自动维护自定义字符串属性。

### 7.2 改善创建体验

- 已有匹配直接打开；仅新建时使用 Obsidian 风格命名窗口。
- 标题由用户确认，可用第一条个人笔记的简短文本作为建议，不调用 AI；目录沿用设置。
- 创建内容继续包含原文、全部个人笔记、来源块链接、返回原文链接。
- 保持现有固定 `author: "[[Jarvis]]"` 字段；它不参与来源身份识别。旧文件不批量处理。
- 本阶段暂不增加 Templater 私有接口依赖。普通模板支持留待真实使用需要。

### 7.3 验证与回退

自动检查缺目录、创建失败、文件重名、并发创建、损坏／缺失来源字段、多个匹配、目标改名、删除后再建、取消创建。实机修改生成笔记的标题和正文后再次提升，确认打开原文件且内容不变。

新元数据采用向后兼容的增量字段；旧来源链接继续保留。回退代码不删除已创建的知识笔记。若旧版无法按新身份去重，回退前明确说明限制并暂停再次创建，而非批量还原用户文件。

## 8. 阶段 D：片段格式减负

依赖前三阶段的来源格式稳定后再做，不与导航功能同时修改整体正文格式。

1. 先生成纯划线、一条笔记、多条笔记、长文本、多关联、嵌套引用／列表六类样例。
2. 对比当前格式与建议格式：减少重复章节标题，时间用简短低强调行展示；仍保留各笔记时间与稳定块 ID，不先删除记录。
3. 在普通 Markdown、阅读模式、实时预览和块嵌入中检查原文与个人想法是否清楚，Callout 整体引用是否完整。
4. 让用户比较可见样例后再决定布局。这一阶段的视觉选择会影响日常编辑，不在文档阶段视为已确认。
5. 解析器先支持旧、新格式，所有界面继续使用同一解析结果；新建内容采用选定格式，旧内容不自动迁移。
6. 对无法识别的片段提示具体文件和块 ID，停止该片段的破坏性写入。日志不保存完整正文。

验收必须覆盖嵌套 Markdown、用户手改、删除单条笔记、保存重载和跨界面一致性。回退兼容性用旧解析器样例验证；不能以“格式更简洁”为理由牺牲可编辑内容。

## 10. 人工检查重点

首阶段重点看：从普通笔记点击后是否回到正确书籍和正确文字；原有阅读标签和正在写的笔记是否得到保留。

完整方案重点看：在已有主题笔记中使用摘录是否顺手；来源能否追溯；重命名、手工编辑和再次打开后，内容是否仍符合个人知识库习惯。

自动测试验证规则和异常处理，实机测试验证已覆盖场景。书籍结构差异、第三方主题和真实长期使用仍需观察，不能据此承诺所有 EPUB 和编辑方式均已覆盖。
