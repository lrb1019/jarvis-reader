# 代码梳理第四批实施与验收

Task: C05，自定义封面写入及缓存登记移出 LibraryApp。
Task type: 最小职责整理。
User scenario: 书架菜单更换封面，将浏览器压缩后的 JPEG 保存至配置目录。
Current behavior: UI 内创建目录、创建或覆盖图片、登记缓存，部分异步失败只日志记录或未捕获。
Reproduction: 跟踪 handleCustomCoverUpload、saveBookCoverCacheEntry 和 CoverCacheService。
Root-cause evidence: UI 直接调用 Vault 写入权威图片文件；事务顺序为图片后缓存。
Target behavior: UI 保留读图／canvas压缩，已有封面服务文件承载写入用例，main 适配 Vault；失败显示通知。
Completion criteria: 文件写入移出UI、保留命名／缓存／压缩规则、失败行为明确，完整验证及实机范围有记录。
Scope: LibraryApp、cover-cache-service、main适配、内存测试及生成包。
Explicitly excluded: 改图片大小／样式／数据格式、原图备份及回滚机制、删除孤立图片、进度或其他整改、依赖升级、提交发布。
Affected data and files: 正常操作仍写用户配置目录的 cover_basename.jpg 和独立封面缓存；本次测试仅内存对象，不替换用户实际封面。
Automated verification: 创建／替换／重载、元数据保留、根目录、目录冲突、图片失败不登记缓存、缓存失败保留图片且旧缓存不改、完整 verify。
Obsidian verification: 仅 Obsidian-test 重载、现有封面显示、更换封面菜单及文件选择器取消；真实图片保存／替换不本轮实测。
Failure handling: 抛出服务错误，UI通知并记录日志；图片写成功缓存失败不自动回退图片，保持原顺序，不宣称原子事务。
Rollback: 仅还原本批三个源码差异、测试和生成产物，保留前几批与已有文档。
Documents to update: 本记录、当前清单、项目管理02／03／04。
