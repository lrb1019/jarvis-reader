# 恢复原始封面

Task: 自定义封面可恢复到EPUB原封面。
Task type: 补齐已确认缺失的恢复操作。
User scenario: 上传新封面后希望撤回。
Current behavior: 仅有更换封面菜单，无恢复入口。
Reproduction: 用户已实测更换成功，源码菜单及缓存服务没有恢复操作。
Root-cause evidence: vaultPath覆盖原dataUrl展示，保存保留EPUB dataUrl，但未提供解除覆盖操作。
Target behavior: 自定义封面菜单显示恢复原始封面，保存后即时显示原图；未提取原图时重新提取。
Completion criteria: 保存／重载／失败测试通过，测试库菜单与恢复显示验收。
Scope: CoverCacheService恢复操作、main调用及书架菜单。
Explicitly excluded: 删除用户上传图片、改书籍、阅读状态、提交发布、日常库。
Affected data and files: 单本封面缓存；保留自定义图片、元数据及EPUB。
Automated verification: 原图与元数据保留、上传文件不删、重载、重复恢复、缺失条目、写失败保持旧状态、未提取原图。
Obsidian verification: 测试库重新加载，菜单恢复及重载后显示。
Failure handling: 保存失败不改变内存自定义覆盖，菜单提示原因。
Rollback: 撤回本任务新增服务／main方法与菜单，恢复背景队列展开缓存规则，重建main.js；不回退其他累积改动。
Documents to update: 03／04及本记录。

实现：清除vaultPath和isCustom，保存已有原图和元数据，不删除图片文件。书架重新触发提取队列，后台提取提交使用当前缓存，避免旧快照恢复自定义覆盖。

验证：216项完整verify通过（类型、strict、测试、构建、main.js语法），diff检查通过。新增3项恢复／重载与失败测试。实机当前旧菜单仅有更换封面；原自定义图片仍在，未执行恢复。UI左键／快捷键无响应，右键可读取旧菜单；请求用户重开测试库后继续验收，不能宣称新菜单或真实恢复已验收。

解锁／重开后实机收口：当前原封面状态无恢复菜单；通过正常saveCustomCover以保留图片重新应用自定义封面，新建书架出现「恢复原始封面」。点击菜单后即时恢复EPUB黄色原图。关闭书架、停用启用插件并重开，缓存custom=false、vaultPath不存在、原图dataUrl存在、上传文件仍在；菜单恢复项消失。最后保持原封面，控制台关闭。216项完整verify及diff检查通过；未本轮重新走系统图片选择器，真实写入失败用内存自动测试覆盖。先前UI阻断记录为历史。
