# 图书库空白修复

Task: 关联读书笔记不存在时恢复图书库显示。
Task type: 故障修复。
User scenario: 用户打开图书库，仅有标题，书架为空白。
Current behavior: React LibraryApp effect 调用 findBookNote 抛错，组件树退出。
Reproduction: 测试库 books 两本 EPUB 存在，关联 Markdown 移至 Reading Notes 后打开图书库。
Root-cause evidence: 控制台关联笔记不存在错误及 LibraryApp 组件栈；LibraryView root 存在但 contentEl 为空；两个 remembered 路径仍在原目录，当前 Markdown 路径已变。
Target behavior: 单本笔记关联错误只影响该书笔记资料，不阻止整个书架及其他书籍显示；错误可见且不误建笔记。
Completion criteria: 两本书恢复封面／进度；原关联索引不变；错误可见；自动验证通过。
Scope: 书架笔记映射和资料读取的错误隔离、缓存变更刷新及聚焦回归测试。
Explicitly excluded: 自动修复 Markdown 路径、移动文件、数据迁移、发布及日常库部署。
Affected data and files: 只读投影，原 Markdown／bookNotePaths／高亮等权威记录不改。
Automated verification: npm run verify；单书缺关联、正常／新书共存、恢复／删除／空列表清除旧投影。
Obsidian verification: 原始真实故障重载后显示两本书、封面、8 条笔记计数、进度及两份笔记路径失效提示；关联记录重载前后相同。
Failure handling: 每书错误独立记录，保留严格写入保护，资料读取不抛至 React；元数据缓存变动触发投影刷新。
Rollback: 恢复 UI 投影源码重新构建，不需恢复用户数据。
Documents to update: 改动日志、接续说明及故障复盘。

## 故障复盘

Date: 2026-10-01
Impact: 整个图书库空白，书籍文件仍存在。
User-visible behavior: 打开图书库只有页标题，无书架。
Direct cause: remembered 笔记路径不存在时 findBookNote 抛错，UI effect 没有隔离。
Systemic root cause: 防止误建替代笔记的写入保护也用于只读书架，但调用方未定义缺失关联的展示行为。
Why tests missed it: 先前路径跟随只验收 EPUB 单文件，未覆盖关联 Markdown 移动后的书架 React 循环；上轮验收中恢复原目录后未检查实际书架完成渲染。
Recovery: 只读界面隔离异常，显示可诊断提示，原记录保留。
Final fix: 统一书架笔记投影按书捕获异常，清理失效旧投影；资料读取使用相同投影，元数据变化刷新。
New prevention gate: 缺失关联必须有正常书／新书共存回归，实际 Markdown 缺失状态重载书架验收；不得用改目录或写空记录隐藏问题。

## 验证限制

164 项测试、普通／严格类型、生产构建、main.js 语法通过。缺失关联与恢复清理为纯投影测试，真实测试库原始故障已实机确认并恢复书架。自动 Markdown 改名／移动跟随仍未实现；缺关联书的阅读资料与原笔记来源链接可能仍需修复。未制造真实磁盘故障、未测试全主题与全平台。没有改动权威笔记内容／关联路径，未提交发布。
