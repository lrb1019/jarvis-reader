# I04 完整笔记输入类型

Task: 显式声明Markdown完整内容的服务输入类型。
Task type: 类型边界整理。
User scenario: 多条笔记及AI／关联内容从Markdown读取后编辑、替换、展示时保留完整内容。
Current behavior: BookHighlight没有commentEntries／aiSections，序列化和EpubView靠any附加字段，服务签名没有描述实际输入。
Reproduction: 沿读取、更新、服务、文档与序列化调用链搜索；现有多条／复杂Markdown及冲突测试作为行为基线。
Root-cause evidence: formatHighlightNoteBlock两处any读字段；EpubView更新四处any写字段，读回对象以any压入BookHighlight数组。
Target behavior: 复用HighlightNoteDetails字段类型，新增仅内存传递的HighlightNoteInput，接通序列化、文档、服务和阅读器边界。
Completion criteria: 类型检查、现有完整测试、构建及生成主程序字节对照；数据格式不变。
Scope: 输入类型及直接消费者签名／断言。
Explicitly excluded: 索引字段和迁移、全仓strict、pendingSelection整体重写、数据、提交发布。
Affected data and files: 类型及直接消费者，main.js只通过构建生成；没有新增存储字段或写入路径。
Automated verification: npm run verify通过普通／strict类型检查、230项现有测试、生产构建及main.js语法。涉及的文档插入／替换／多条笔记／复杂Markdown／冲突保护、事务和知识笔记测试均在完整套件中。main.js SHA-256与本轮前一致（I03已构建基线），无运行字节变化；差异检查通过。类型整理未新增镜像行为测试。
Obsidian verification: 本轮没有重复实机操作或重载；产物逐字节一致，沿用已加载I03主程序及既有笔记保存／重开／展示／知识提升验收记录，不声称本轮重新验证这些操作。
Failure handling: 编译错误追踪直接调用，不扩大为全局any清理。
Rollback: 撤销本轮类型与断言差异，保留I01—I03；必要时重建。
Documents to update: 本文、增量清单、03、04。

## 保留边界

BookHighlight和PersistedBookHighlight保持原字段；新增类型只描述内存中的可选完整Markdown内容，允许既有缺失Markdown回退与新高亮单条comment输入。pendingSelection整体any、其他读写参数和历史候选没有扩大清理。highlight-core对文档类型的引用为type-only，不增加运行依赖。
